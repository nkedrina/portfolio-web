# Карта проекта portfolio-web

## 1. Краткий обзор

Это статический одностраничный сайт-портфолио художницы Насти Кедриной. Проект не использует сборщик и не содержит явных файлов зависимостей (`package.json`, lock-файлы не найдены). Основная архитектура — несколько HTML-точек входа с общими CSS/JS-файлами и SPA-подобной маршрутизацией по `location.hash`.

Проверены корневые файлы, все HTML-страницы, основные JavaScript-файлы, структура `data/`, `images/` и `projects/`, а также общий объём и типы файлов. Приложение не запускалось и визуальный результат не проверялся.

### Назначение папок

- `data/` — текстовые исходники контента для разных разделов и документы для скачивания; используется как справочная редакционная информация и хранит PDF-файлы.
- `images/` — общие изображения сайта: герои в светлой/тёмной теме, портреты художницы и favicon-иконка.
- `projects/` — медиа-контент и обложки проектов. Всего найдено 32 каталога проектов. Каталоги имеют нумерацию и человекочитаемые имена, например `30_aqualumina`, `31_sense_of_home_street` и `32_exit`.
- `ai-context/` — служебная документация проекта для последующей работы с кодовой базой.

## 3. Точки входа

### Главная точка входа

`index.html` — основной HTML-документ. Он содержит каркас приложения:

- фиксированный `<header class="hdr">` и навигацию;
- переключатель темы `#themeBtn`;
- `<main id="main">`, куда динамически добавляются страницы;
- `<footer id="footer">`;
- элементы модального окна проекта `#modal` и быстрого предпросмотра `#quick`;
- контейнер уведомлений `#toast`;
- подключение `data.js`, `utils.js`, `render.js` в указанном порядке через `defer`.

`index.html` также до загрузки основного кода сохраняет или считывает тему из `localStorage` и устанавливает `data-theme` на корневом элементе, чтобы избежать переключения темы после рендеринга.

### Дополнительные HTML-точки входа

Все остальные HTML-файлы являются почти одинаковыми оболочками SPA:

- `about.html` — оболочка маршрута `/about`;
- `portfolio.html` — оболочка маршрута `/portfolio`;
- `exhibitions.html` — оболочка маршрута `/exhibitions`;
- `contacts.html` — оболочка маршрута `/contacts`.

Они используют общий `style.css`, общий каркас header/main/footer/modal и общие скрипты. При загрузке сайт нормализует путь HTML-файла в hash-маршрут в `render.js`. Например, загрузка `portfolio.html` приводит к hash `#/portfolio`.

Есть небольшое различие: `exhibitions.html` и `contacts.html` дополнительно загружают `script.js` перед остальными скриптами. В остальных оболочках `script.js` не подключён. Последующий `data.js` устанавливает актуальный объект `window.PORTFOLIO_DATA`, поэтому дублирующаяся структура данных из `script.js` фактически перезаписывается данным скриптом при наличии обеих загрузок.

## 4. Основные файлы и ответственность

### `data.js`

Ключевой источник данных текущего приложения.

- задаёт базовый URL Vercel Blob;
- экспортирует `window.toAssetUrl()` для преобразования локальных путей медиа в удалённые URL;
- экспортирует `window.normalizeAssetUrls()` для рекурсивной нормализации путей внутри массивов и объектов;
- содержит данные художницы `A`;
- содержит категории `CATS`;
- содержит порядок проектов в категориях `PROJECT_SECTION_ORDER`;
- содержит массивы проектов `PROJECTS` и выставок/мероприятий `EXH`;
- нормализует медиа-пути и публикует всё через `window.PORTFOLIO_DATA = { A, CATS, PROJECTS, EXH }`.

Ключевые поля проекта: `id`, `title`, `year`, `medium`, `desc`, `concept`, `tech`, `exhibitions`, `links`, `image`, `video`, `blocks`, `tile`, `featured`, `cat`, `art`. В некоторых проектах есть структурированные блоки галереи `full`, `grid` и `video`.

### `utils.js`

Небольшой модуль общих вспомогательных функций. Создаёт и публикует `window.PORTFOLIO_UTILS`:

- `$()` — выбор элемента через `querySelector`;
- `esc()` — экранирование HTML;
- `sortedEx()` — сортировка массива выставок по убывающей дате;
- `pad2()` — форматирование числа с ведущим нулём;
- `place()` — сбор строки местоположения;
- `cityLine()` — сбор строки городов;
- `TAG()` — формирование подписи вида `текст + dot + @nkedrina`;
- `RM` — признак настройки prefers-reduced-motion.

### `render.js`

Основная логика приложения и главный исполняемый модуль интерфейса. Он зависит от `window.PORTFOLIO_DATA` и `window.PORTFOLIO_UTILS`, поэтому должен загружаться после `data.js` и `utils.js`.

Основные механизмы:

- проверка и генерация Canvas-картинок для проектов по параметрам `art`;
- ленивая загрузка изображений через `IntersectionObserver`;
- резервная загрузка медиа через локальный путь после ошибки Blob-URL;
- адаптивная раскладка сеток галерей проекта;
- маршрутизация по hash;
- рендеринг основных страниц;
- фильтрация портфолио по категориям;
- модальное/полностраничное отображение проектов;
- быстрый preview проекта на главной;
- переключение светлой и тёмной темы;
- управление прокруткой и скрытием header;
- обработка клавиатуры и focus trap для диалогов;
- заполнение footer и навигационных элементов;
- синхронизация hero-изображений с темой.

### `script.js`

Отдельный автономный блок с более ранней копией структуры данных. Содержит объект художницы, категории, массив проектов и выставок и в конце устанавливает `window.PORTFOLIO_DATA`. Он загружается только в `exhibitions.html` и `contacts.html`, но эти страницы затем загружают `data.js`, который определяет актуальный объект данных той же самой переменной. Поэтому документируется как устаревший/дублирующий модуль данных; назначение основной модели считается подтвержденным для `data.js` по фактическому включению во все HTML-файлы.

### `style.css`

Единая таблица стилей всего приложения. Содержит:

- CSS-переменные для обоих тем и типографики;
- стили header/navigation/footer и общих кнопок;
- hero-блок главной страницы;
- секции обо мне, портфолио, выставок и контактов;
- фильтр портфолио и карточки проектов;
- страницы проектов, галереи, сетки и адаптивные размеры;
- модальное окно и quick preview;
- переходы, анимации и состояния видимости;
- media queries и отдельные переопределения для мобильных размеров;
- стили светлой и тёмной тем;
- стили загрузки медиа и project-gallery.

Верхний блок задаёт переменные и базовые элементы. Последние блоки дополнительно переопределяют навигацию, hero и галереи проекта для дизайна конкретного адаптивного состояния.

## 5. Маршруты и страницы

Маршрутизация реализована внутри `render.js`; отдельного framework/router нет.

| Hash-маршрут | Функция рендера | Назначение |
|---|---|---|
| `#/` | `home()` | Главная: hero, кратко обо мне, избранные проекты, избранные выставки, контакты |
| `#/about` | `about()` | Биография, образование, воркшопы, artist statement |
| `#/portfolio` | `portfolio()` | Категории и сетка всех проектов с фильтрацией |
| `#/exhibitions` | `exhibitions()` | Отдельные списки выставок и фестивалей/мероприятий |
| `#/contacts` | `contactsPage()` | Заголовок страницы и блок контактов |
| `#/portfolio/<project-id>` | `projectHTML(i)` | Детальная страница конкретного проекта |

Сопоставление `location.pathname → location.hash` находится в `normalizeInitialPath()`:

- `index.html` → `#/`
- `about.html` → `#/about`
- `portfolio.html` → `#/portfolio`
- `exhibitions.html` → `#/exhibitions`
- `contacts.html` → `#/contacts`

На `#/contacts` маршрут рендерит главную страницу и прокручивает к блоку `#contacts`; детальная обработка этого исключения находится в `route()`.

## 6. Основные компоненты интерфейса

Компоненты в этом проекте представляют собой функции генерации HTML-строк внутри `render.js`, а не отдельные компоненты-файлы.

- `home()` — главный экран и разделы главной;
- `about()` — страница художницы;
- `portfolio()` и `pfHTML()` — портфолио и фильтрованные сетки;
- `mosaic()` — чередующаяся разметка карточек проекта;
- `exhibitions()` и `exRow()` — страницы и строки выставок;
- `contactsBlock()` и `contactsPage()` — общий блок и отдельная страница контактов;
- `pcard()` — карточка проекта для главной и портфолио;
- `projectHTML()` и `detailHTML()` — детальная композиция проекта;
- `projectDescription()` — текстовое описание проекта;
- `projectBlocks()` и `projectPrimaryMedia()` — выбор медиа-блоков галереи;
- `openQuick()` / `quickHTML()` — быстрый предпросмотр проекта;
- `openModal()` / `closeModal()` — legacy-механизм модального проекта, который в текущей hash-маршрутизации может соотноситься с проектами;
- `toggleTheme()` — переключение темы;
- `hydrate()` — активация ленивой загрузки, анимаций появления и расчёта галерей;
- `render()` и `route()` — жизненный цикл содержимого страницы.

## 7. Связи и поток данных

```text
HTML-оболочка
  ├── localStorage theme init → data-theme
  ├── data.js
  │     └── window.PORTFOLIO_DATA
  ├── utils.js
  │     └── window.PORTFOLIO_UTILS
  └── render.js
        ├── читает PORTFOLIO_DATA
        ├── читает PORTFOLIO_UTILS
        ├── слушает hashchange и DOM-события
        ├── рендерит HTML в #main
        └── обновляет header, footer, modal, quick и theme

PORTFOLIO_DATA.PROJECTS
  ├── карточки портфолио/главной
  ├── фильтр портфолио
  ├── project detail
  └── gallery/media blocks

PORTFOLIO_DATA.EXH
  ├── избранные мероприятия главной
  └── страницы выставок/фестивалей

/assets:
  data.js normalizeAssetUrls → Vercel Blob или локальный путь
  projects/*/cover.png → карточки и cover-hero
  projects/*/photos/* → detail-галареи
  images/* → hero и портреты
  data/*.pdf → кнопки скачивания
```

Фактический порядок загрузки для основного сценария: `data.js` → `utils.js` → `render.js`. В `exhibitions.html` и `contacts.html` перед ними дополнительно расположен `script.js`, но затем `data.js` переопределяет глобальные данные актуальными значениями.

## 8. Ключевые механизмы

### Тема

В inline-скрипте всех HTML-файлов тема из `localStorage` сохраняется как `light` или `dark`, со значением по умолчанию `dark`. Кнопки `toggleTheme()` переключают атрибут `data-theme`, сохраняют выбор и при наличии используют `document.startViewTransition`.

Стили темы находятся в `style.css`, а пути theme-specific hero/portrait дополнительно выбираются в `render.js` и `data.js`.

### Изображения и медиа

`data.js` нормализует локальные медиа-пути в URL Vercel Blob. `render.js` содержит резервный возврат к локальному пути при ошибке загрузки Blob-URL.

Для проектов без реального изображения модуль создаёт Canvas-изображение из параметров `art.style`, `art.seed` и `art.pal`. Реализации генерирующих эффектов находятся в объекте `ART` внутри `render.js`: bars, tunnel, waves, vortex, streaks, blobs, shards и texture.

### Галереи проектов

`detailHTML()` интерпретирует блоки проекта `full`, `grid`, `video` или резервные заглушки. `layoutProjectGalleries()` пересчитывает ширину строк и количество колонок с учётом ширины окна, а `layoutProjectMedia()` отвечает за дополнительную обработку медиа. Resize-событие запускает перерасчёт с задержкой.

### Портфолио

Категории берутся из `CATS`, проекты — из `PROJECTS`, а порядок внутри каждой категории дополнительно задаётся `PROJECT_SECTION_ORDER`. Фильтр хранится только в переменной `pfCat` и обновляет сетку без перезагрузки страницы. Mosaic-разметка чередует строки из 3 и 2 проектов с адаптивной шириной колонок.

### Проектные описания

Расширенные описания конкретных проектов хранятся в объекте `PROJECT_DESCRIPTIONS` внутри `render.js`. Если для `id` нет записи, карточка/detail не получает дополнительного описания и использует поля самого проекта из `PROJECTS`.

## 9. Внешние ресурсы и зависимости

Проект использует следующие внешние CDN/сервисы, обнаруженные в HTML и JS:

- Google Fonts — шрифт Moderustic;
- Font Awesome 7.0.1 — иконки через CDN;
- Vercel Blob — хранилище медиа по адресу `lnhqdym4r8iqqhi1.public.blob.vercel-storage.com`;
- Instagram, Behance, Telegram и PDF-ссылки из данных проекта.

Других JavaScript-фреймворков, npm-пакетов или локальных библиотек в найденных конфигурациях нет. Обнаруженные зависимости являются CDN/HTTP-ресурсами, а не модулями сборки.
